# 驭舟管理 Web

## 独立电脑网站

`src/site/` 是普通 Vue/HTML 的电脑网站，不使用 UniApp 页面或手机底栏。用户入口为根路径 `/`，经纪销售入口为 `/sales`；三个管理后台仍使用原有 `/admin/` 工程。网站独立使用 `yuzhou_desktop_consumer_token`、`yuzhou_desktop_broker_token` 浏览器会话，角色和组织继续由现有 API 核验。

本地执行 `npm run dev:site`，默认 `http://127.0.0.1:5180/`；API 代理同样读取 `VITE_API_PROXY`。`npm run build:site` 只构建电脑网站到 `dist-site/`。在仓库根目录执行 `npm run release:site` 生成绑定已提交源码与 SHA256 的独立发布包，不构建 App、WGT 或后台。

腾讯云通过发布包内的 `install-site.py` 激活网站，保留当前 API、管理后台、原 H5 资产、安装包、共享上传和两个 App 热更新。网站资产与旧资产同时保留，发布失败恢复原 current 和本站 Nginx 配置。原 `/consumer/`、`/broker/` 网页根入口分别转向电脑网站 `/`、`/sales`，App 本身仍使用原 API 和 WGT 地址。

消费者网站包含船艇/商品/服务浏览与下单、个人中心、订单合同和学习活动；经纪销售工作台包含客户、代客配置报价、合同履约、预约、结算和会话。课程不单独售卖，PDF 采用下载、线下签署后确认，支付未配置的失败结果按实际接口显示。原 1.0.13（113）两个 App 保持不变。

`node tests/site-consumer-browser.cjs`、`node tests/site-broker-browser.cjs` 为独立离线浏览器夹具测试，拦截全部 API，不代表真实支付、上线数据或设备验收。消费者脚本自行启动并关闭本地 5183 测试服务；经纪脚本需先启动本地网站，可用 `SITE_TEST_ORIGIN` 指定地址。其他原管理端检查保持下面的约定。

一个 Vue 3 工程提供三套入口，菜单和会话分别管理；真实权限、组织隔离、状态与文件授权均由后端执行。

| 入口 | 业务 |
| --- | --- |
| `/admin/platform` | 全平台资源、入驻/实名、组织账号、交易合同、退款、利润确认、分红配置、提现与审计 |
| `/admin/merchant` | 自有船艇、升级养护、活动、商家直接销售订单；不开放平台直营商城与经纪公司订单 |
| `/admin/agency` | 本公司经纪人、客户、订单合同及履约 |

## 本地运行

使用 Node.js 22.12 或更高版本，在本目录执行 `npm ci`、`npm run dev`。开发地址为 `http://127.0.0.1:5173/admin/`，`/api` 默认代理至 `http://127.0.0.1:8088`。

配置参考 `.env.example`。浏览器可见配置只能包含公开端点；支付、数据库、签名及其他私密配置放在后端和发布环境。生产 API 默认同域 `/api/v1`，目标域名为 `yuzhou.ourideas.top`。部署时将三个入口及其子路由重写到 `/admin/index.html`。

## 操作与边界

- 资源编辑采用 `title`、整数 `price_cents` 与业务 `payload`；课程章节/视频/题目、船艇参数、图片和适用券类型均有操作表单。
- 课程奖励配置支持徽章、成长值、优惠券、养护券、实物礼包及活动邀请资格；平台记录实物交付凭据。积分兑换拒绝时由服务端退回成长值和库存。
- 联合活动通过参与商家统一社会信用代码选择，指定商家在自身入口审核。轮播内容、资讯置顶、评论人工审核和官方回复均通过真实接口操作。
- 预约支持确认、完成与取消；咨询限本人参与的会话；反馈支持平台回复、处理状态及用户站内通知。
- 管理子角色必须保持基础身份与组织归属，菜单按服务端 `permissions` 收窄；服务端继续核验所有接口。统计、用户业务历史与 `.xlsx` 导出均使用授权接口。
- 金额输入最多两位小数，提交转换为整数分。百分比转为整数 basis points，服务端再次校验。
- 合同、营业执照和申请材料私有上传；文件下载携带当前会话，仅访问配置 API 的同源鉴权路径。合同登记、审核与确认按版本执行。
- 修改资源提交服务端版本号，409 不会强行覆盖。失败操作保留输入，实际结果以服务端返回为准。
- 会员使用明确的六个月赠予指令；分红不默认选受益人，最多一位本单经纪人和一位有效会员。
- 真实支付和提现通道未配置时显示服务端失败。退款测试通道只有 `/bootstrap` 明确提供测试能力时才显示；此开关的最终校验在后端。
- 各入口 token 仅在当前浏览器会话中按角色存放。前端拒绝角色不符的登录结果，不能通过入口切换获取角色。

## 检查

`npm run check` 执行 Vue 类型检查和金额/入口/私有附件来源单元检查。`npm run build` 构建三入口同一产物至 `dist/`。

`npm run test:browser` 使用 Playwright 验证页面行为，需要先启动本 Web 服务且已安装 Chromium（首次可执行 `npx playwright install chromium`）。该脚本拦截 API，使用显式合成夹具，覆盖拒绝错误角色、课程编辑、资源/合同审核、整数利润、退款失败保留状态、测试通道隐藏以及三角色菜单。它不能证明服务端业务或组织隔离通过。截图默认写入 `/tmp/yuzhou-web-ui-fixtures`，可用 `WEB_TEST_OUTPUT` 改写。

`RUN_DEV_WEB_MUTATIONS=1 npm run test:live` 验证三个 Web 的真实本地接口交易闭环；`npm run test:live:content` 与 `npm run test:live:operations` 同样需要此环境开关，分别验证课程活动服务、运营权限及报表。先启动本地 Web/API，启用开发测试支付，准备后端私有开发账号文件；内容测试还使用交易测试生成的合成 PDF。脚本不打印或保存账号口令和 token，只添加明确标记的合成开发资料，报告与截图写入被忽略的 `test-results/`。内容测试采用报告式学习进度，不能证明视频实际观看；实物发放记录也不代表真实配送。

真实支付回调/实际转账、短信、真机及生产部署需独立记录；构建、夹具检查及开发测试交易不等于这些验收通过。具体覆盖与证据范围见 [COVERAGE.md](COVERAGE.md)。
